# [Fable5/Opus] P2-7: メインウィンドウのリサイズ方針の再設計（設計タスク → 実装は別途Codex可）

## 前提コンテキスト
- 対象: Tauri 2 + React のデスクトップアプリ。作業ディレクトリはリポジトリの `apps/pilotbell`。
- メインウィンドウは2モードを行き来する:
  - **compact**（コマンドパレット風）: 620x190 / min 420x160。空セッション時。
  - **chat**: 760x720 / min 420x620。履歴・添付・プレビューが存在する時。
- 切替ロジックは `src/hooks/useTauriWindowShell.ts` の 46-59行目（レイアウト定義）と
  155-183行目（適用エフェクト）。モード遷移のたびに
  `setMinSize` → `setSize(固定値)` → `center()` を実行する。
  maximized 中は setSize/center をスキップする。
- `tauri_plugin_window_state`（`src-tauri/src/shell.rs` 参照）がウィンドウ非表示時に状態保存している。
- グローバルショートカット（Alt+Space）でパレット表示/非表示するランチャー的な使い方が想定されている。

## 現状の問題
1. compact ⇔ chat 遷移のたびに `setSize` + `center()` でユーザーが調整した
   ウィンドウサイズ・位置が毎回破棄され、ウィンドウが画面中央にジャンプする。
2. chat の固定高さ 720px は小型ディスプレイ（例: 768px 高、タスクバーあり）で
   作業領域からはみ出しうる。minHeight 620 も同様に過大の可能性。
3. `clearSession`（チャットクリア）でも compact に戻り、再度センタリングが走る。

## 設計してほしい論点
1. chat モードのサイズ・位置をユーザーが変更した場合、次回 chat 遷移時にそれを復元すべきか。
   復元するなら保存先（メモリのみ / localStorage / tauri-plugin-window-state との整合）をどうするか。
2. `center()` を廃止して現位置を維持しつつ、ウィンドウが作業領域（モニタの可視領域）から
   はみ出す場合のみクランプする方式の是非と実装方法
   （Tauri 2 の `currentMonitor()` / `availableMonitors()` / work area の取り扱いを含む）。
3. chat の初期高さを固定 720 ではなく `min(720, workArea.height - margin)` のように
   動的に決めるべきか。minHeight も同様。
4. compact への縮小時（クリア時・全削除時）の挙動: 即縮小がよいか、
   ランチャー的UXとして妥当か（ショートカットで隠す→次回表示時に縮小、等の代替案）。
5. マルチモニタ・DPIスケーリング（Windowsの125%/150%）での LogicalSize の妥当性。

## 成果物
- 上記論点それぞれへの決定と理由（トレードオフ込み）。
- `useTauriWindowShell.ts` の修正方針を、別モデル（Codex）にそのまま渡せる粒度の
  実装仕様（関数シグネチャ・保存キー・擬似コードレベル）に落とすこと。
- Tauri 2 API の使用箇所は実在するAPI名で（憶測の場合はその旨を明記し要検証タグを付ける）。

## 制約
- パレットとしての即時表示性（ショートカット→即入力）を損なわないこと。
- maximized 状態の既存ハンドリング（スキップ）は維持または改善。
